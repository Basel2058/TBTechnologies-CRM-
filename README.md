# TBT CRM — نظام إدارة العملاء والمكالمات

نظام عربي (من اليمين لليسار) لإدارة عملاء شركة TBT ومتابعة عمل موظف مركز الاتصال: من أول مكالمة حتى الاشتراك الشهري.

> هذا النظام **لا يسجّل المكالمات صوتياً ولا يستخدم الذكاء الصناعي** — حسب ما اتفقنا. الموظف يتصل من هاتف المكتب الأرضي ويسجّل النتيجة في النظام.

---

## ماذا يفعل النظام؟

**للموظف (موظف الاتصال):**
- **قائمة اتصال يومية مرتّبة تلقائياً:** المتابعات المستحقة أولاً، ثم العملاء الجدد.
- **وضع الاتصال:** زر «ابدأ الاتصال» يعرض العميل التالي فوراً بعد كل مكالمة، مع رقمه بخط كبير وزر نسخ.
- **تسجيل نتيجة المكالمة بضغطة** (أو بالأرقام 1–9 على لوحة المفاتيح): لم يرد، مشغول، رقم خطأ، اتصل لاحقاً، سأفكر، مهتم، حُجز موعد، غير مهتم، تم البيع.
- **قواعد تلقائية:**
  - من لا يرد يعود للقائمة وحده بعد يوم، ثم يومين، ثم 3 أيام، وفي وقت مختلف من اليوم. بعد 5 محاولات تتوقف المحاولات.
  - «اتصل لاحقاً» و«مهتم» و«سأفكر» تتطلب تحديد يوم وساعة للمتابعة، ولا يمكن تركها «بعدين».
  - «غير مهتم» يتطلب اختيار **سبب الرفض**.
  - «عنده برنامج آخر» يسأل متى ينتهي عقده، والنظام يذكّر بالاتصال قبل انتهائه بشهر.
- **نص المكالمة والردود على الاعتراضات** تظهر بجانب المكالمة، لكل تطبيق.
- **رسائل واتساب جاهزة** (تأكيد موعد، تذكير، بعد الغياب، ترحيب...) تُفتح باسم العميل وموعده، ويبقى على الموظف الضغط على «إرسال».

**المواعيد ومنع الغياب:**
- بعد حجز موعد يظهر فوراً زر «أرسل تأكيداً بالواتساب».
- قائمة «تحتاج تأكيداً» لمواعيد اليوم وغداً، وقائمة «مواعيد مضت — هل حضر؟».
- **لم يحضر:** العميل يصعد لأول قائمة الاتصال فوراً. بعد الغياب الثاني ينتقل لمتابعة بعد شهر.
- تأجيل الموعد يحفظ تاريخ المواعيد السابقة.

**للمدير:**
- **مراحل البيع (Kanban):** جديد ← تم التواصل ← مهتم ← موعد عرض ← عرض سعر ← تفاوض ← مشترك / غير مهتم. تُنقل البطاقات بالسحب.
- **التطبيقات:** السعر، الباقات، نص المكالمة، والردود على الاعتراضات.
- **الاشتراكات الشهرية:** الدخل الشهري الثابت (MRR)، والإلغاءات مع **سبب الإلغاء**.
- **فرص بيع جاهزة:** مشتركون يمكن أن يشتروا تطبيقاً آخر، عقود منافسين تنتهي قريباً، وعملاء رفضوا قبل أكثر من 3 أشهر.
- **التقارير:**
  - عدد المكالمات ونسبة الرد والتحويل.
  - **لماذا يرفض العملاء** (لكل تطبيق)، وماذا كتبوا بالضبط.
  - **الغياب عن المواعيد:** حسب المدة بين الحجز والموعد، وحسب التأكيد المسبق، ونوع الموعد، ونوع المصلحة.
  - الإيرادات، وأداء الموظفين، وأي نوع مصالح يشترك أكثر.
- **استيراد العملاء من Excel أو CSV:** النظام يخمّن معنى كل عمود (عربي/عبري/إنجليزي)، ويوحّد صيغ الأرقام، ولا يضيف رقماً مكرراً.
- **تصدير Excel** و**نسخة احتياطية** بضغطة.
- **الصلاحيات:** الموظف يرى العملاء المسندين إليه فقط، ولا يستطيع الحذف أو التصدير أو رؤية التقارير والإعدادات.

## التشغيل على كمبيوتر المكتب (Windows)

1. ثبّت **Python 3.12 أو أحدث** من [python.org/downloads](https://www.python.org/downloads/). أثناء التثبيت **ضع علامة على «Add python.exe to PATH»**.
2. نزّل المشروع من GitHub: الزر الأخضر **Code** ← **Download ZIP**، ثم فك الضغط في مجلد ثابت، مثلاً `C:\TBT-CRM`.
3. اضغط مرتين على **`start-windows.bat`**.
   - أول مرة يأخذ دقيقة لتجهيز كل شيء، ثم يطلب منك إنشاء **حساب المدير** (اسم دخول بالإنجليزية وكلمة مرور).
4. افتح المتصفح على: **http://localhost:8000**

**ملاحظات:**
- **اترك النافذة السوداء مفتوحة** طوال العمل. إغلاقها يوقف النظام.
- **إذا كان الموظف يعمل على كمبيوتر آخر في المكتب:** النافذة تكتب عنواناً مثل `http://192.168.1.20:8000`، يفتحه الموظف من متصفح جهازه. إذا لم يفتح، اسمح لـ Python في جدار الحماية (Windows Firewall) عندما يسألك.

**على Mac أو Linux:** شغّل `./start.sh` في الطرفية بدلاً من الملف السابق.

## التشغيل على سيرفر (للدخول من أي مكان)

إذا أردت أن تفتح النظام من البيت أو من الجوال، شغّله على سيرفر صغير (VPS) فيه Docker:

```bash
cp .env.example .env
```

عدّل في ملف `.env` اسم النطاق وكلمة مرور المدير، ثم شغّل:

```bash
docker compose up -d --build
```

ضع أمامه **HTTPS** (مثلاً عبر Caddy أو Nginx)، واجعل `DJANGO_HTTPS=1`. كل البيانات تُحفظ في مجلد `data` بجانب الملفات.

## أول خطوات بعد التشغيل

1. **التطبيقات** ← «تطبيق جديد»: الاسم، السعر الشهري، الباقات، ونص المكالمة (يأتي نموذج جاهز لتعدّله).
2. **الإعدادات ← المستخدمون** ← «مستخدم جديد» لموظف الاتصال بدور «موظف مبيعات».
3. **استيراد عملاء** ← ارفع ملف Excel، واختر الموظف الذي يُسند إليه العملاء.
4. راجع في **الإعدادات**:
   - أسباب الرفض.
   - رسائل واتساب الجاهزة: عدّل نصّها بأسلوبك، ويمكن إضافة نسخ بالعبرية.
   - الردود على الاعتراضات.

بعدها يدخل الموظف بحسابه ويضغط **«ابدأ الاتصال»**.

## النسخ الاحتياطي

كل البيانات في ملف واحد: `data/tbt_crm.sqlite3`.

من **الإعدادات ← النسخ الاحتياطي** نزّل نسخة **مرة في الأسبوع على الأقل**، واحفظها خارج الكمبيوتر (Google Drive أو ذاكرة خارجية).

> لا تحذف مجلد `data`، ففيه كل العملاء والمفتاح السري للنظام.

## تجربة النظام ببيانات وهمية

لتجربة النظام قبل إدخال عملائك الحقيقيين، استخدم مجلد بيانات منفصلاً حتى لا تختلط البيانات الوهمية بالحقيقية.

على Mac/Linux:

```bash
TBT_DATA_DIR=demo-data .venv/bin/python manage.py load_demo_data --yes
```

```bash
TBT_DATA_DIR=demo-data .venv/bin/python run.py
```

على Windows (في نافذة cmd داخل مجلد المشروع):

```bat
set TBT_DATA_DIR=demo-data
.venv\Scripts\python manage.py load_demo_data --yes
.venv\Scripts\python run.py
```

الدخول: `manager` أو `agent`، وكلمة المرور `demo12345`.

## تحديث النظام لنسخة جديدة

1. أوقف النظام.
2. استبدل ملفات المشروع بالنسخة الجديدة **مع الإبقاء على مجلد `data`**.
3. شغّله من جديد. التحديثات على قاعدة البيانات تُطبَّق تلقائياً.

## For developers

- Django 5.2 LTS, SQLite (WAL), server-rendered templates, Bootstrap 5.3 RTL, vanilla JS. All front-end assets are vendored under `crm/static/vendor`, so no CDN is required.
- Business rules live in `crm/services.py`, phone normalization in `crm/phones.py`, and Excel/CSV import in `crm/importer.py`.
- Configuration is through environment variables (see `.env.example`). Debug mode is off unless `DJANGO_DEBUG=1`. The secret key is auto-generated into the data dir.
- Run the tests:

  ```bash
  python manage.py test crm
  ```

- Dev server:

  ```bash
  DJANGO_DEBUG=1 python manage.py runserver
  ```
